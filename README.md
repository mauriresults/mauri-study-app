# دروسي موريتانيا — Mauri Study

مشروع مستقل عن موقع النتائج الحالي: تطبيق Flutter لـ Android/iOS + Cloudflare Worker API + D1 + R2.

## تحديث التدقيق الفعلي

هذه نسخة تطوير جزئية، وليست تطبيقًا مكتملًا أو إصدار متجر. راجع `docs/VERIFICATION.md` لنتائج الجلسة الحالية؛ الفقرات الأقدم أدناه تصف معلومات النسخة التأسيسية ولا تثبت نجاح البناء أو النشر الحالي.

أُصلحت معالجة HTTP Range وHEAD والتحقق الشرطي بـETag. أُضيف منع التنزيل المتكرر للملف نفسه، والتحقق من النسخة الموجودة، وحفظ الأجزاء باسم مرتبط ببصمة المحتوى، وانتظار الكتابة إلى القرص لتقييد استخدام الذاكرة. تتطلب تعديلات Dart تحقق Flutter قبل الاعتماد عليها.

تتطلب أداة الاستيراد عمود `rights_evidence` عند استعمال `--publish`، وتقرأ الملف من R2 وتحسب SHA-256 قبل فهرسته. احتفاظ الكائن ببيانات SHA-256 التي كتبها المستورد لا يكفي وحده لإثبات سلامته. لا تستبدل الأداة مفتاحًا موجودًا بمحتوى مختلف.

لم تُرفع ملفات تعليمية جديدة ولم يُنشَر Worker المعدل في هذه الجلسة. لم تُنتج APK أو AAB أو IPA. لم تُشغّل اختبارات أجهزة أو وضع الطيران. لا يزال استيراد Drive الآلي والاستئناف بين عمليات تشغيل المستورد وتجهيز المنصتين والتصميم الكامل أعمالًا غير مكتملة.

## الوضع الحالي (31 أكتوبر 2026، بعد النشر)

- أنشئت D1 باسم `mauri-study-app-db` في Cloudflare، وتم تأكيد وجود جداول levels/tracks/subjects/resources.
- تتضمن القاعدة تصنيفات أولية: مستوى واحد، 5 شعب، 5 مواد، **8 ملفات PDF منشورة مبدئيًا**.
- نُشرت Cloudflare Worker API باسم `mauri-study-app-api` وربطت بقاعدة D1 وربط النشر بنسبة 100%.
- تم إنشاء وتفعيل workers.dev على المسار المتوقع `https://mauri-study-app-api.mauri-study-app.workers.dev`، لكن **تعذّر تأكيد استجابة HTTP من بيئة التحقق** بعد إنشاء النطاق.
- شيفرة التطبيق والواجهة الخلفية موجودة هنا؛ لم تُبنَ APK أو IPA بعد.
- **فُعّلت R2، وأنشئت مساحة مستقلة باسم `mauri-study-files` في منطقة WEUR.**
- أُضيف ربط `FILES` (R2) إلى Worker إلى جانب `DB` (D1)، وتحققت استجابة Cloudflare API بالنجاح.
- نُقلت 8 ملفات PDF من المكتبة المصرح بها عبر Google Drive إلى R2، ونُشرت سجلاتها في D1 مع الحجم وبصمة SHA-256. الإجمالي 1,816,924 بايت.
- بقي نقل بقية المكتبة بالتدريج؛ الـ50 GB لم تُنقل بعد. يتطلب تشغيل أداة الاستيراد على جهاز/خادم يدعم تنزيل الملفات وتوثيق R2 API.
- لا توجد صلة تقنية أو بيانات مشتركة مع موقع النتائج، وقد أكد المالك أن الموقع لا يستخدم موارد Cloudflare حاليًا. وإذا بدأ الموقع باستخدام Cloudflare في المستقبل، فقد تشترك خدمات الحساب في حصص وفوترة الاستخدام.

## بنية الملفات

- `app/` Flutter، دعم العربية والفرنسية، الفهرس المحلي، تنزيل وحفظ الملفات، قارئ PDF.
- `backend/` Worker API للقراءة العامة فقط، مخطط D1 وإعداد Wrangler.
- `scripts/bootstrap_flutter.sh` ينشئ ملفات Android/iOS الأصلية ويشغّل التحليل والاختبارات عند توفر Flutter SDK.

## تشغيل التطبيق

1. تثبيت Flutter SDK وAndroid Studio (وعلى macOS، Xcode لنظام iOS).
2. `bash scripts/bootstrap_flutter.sh`
3. شغّل `cd app && flutter run`. العنوان الافتراضي هو `https://mauri-study-app-api.mauri-study-app.workers.dev`، ويمكن استبداله بـ `--dart-define=API_BASE_URL=https://...`.

## نشر API

1. نُشر Worker بالفعل وتم ربط D1 وR2 به. عنوانه المتوقع هو `https://mauri-study-app-api.mauri-study-app.workers.dev`، لكن بيئة التحقق لم تتمكن من الوصول إلى DNS الخارجي؛ يجب اختبار `GET /v1/health` و`GET /v1/catalog` من متصفح.
2. ملف `backend/wrangler.toml` يضبط القاعدة والمساحة الحالية؛ استخدم `npm install` ثم `npm test` لاختبار API، ثم `npx wrangler deploy` بعد تسجيل الدخول لتحديثه عند الحاجة.
3. ارفع المواد المصرح بها إلى حاوية R2 الخاصة بالتطبيق، وأدخل سجلاتها في جدول `resources` مع `object_key` و`file_size` و`sha256` ثم `published=1`؛ لا يوجد مسار إدارة عام أو كتابة مكشوف في API. يوجد نموذج للفهرس في `scripts/library_manifest.example.csv`، وأداة دفع محلية في `scripts/import_library.py` تستخدم اعتماداتك المحلية دون وضعها في التطبيق.
4. لا تضع أي أسرار في Flutter. اختبر التطبيق على Android وiOS قبل الإطلاق.

## مبادئ العزل والأمان

- ممنوع تعديل جداول الموقع الحالي أو استدعاء API الخاصة به.
- لا تضع رموز Cloudflare أو أسرار الإدارة في التطبيق أو المستودع.
- الحساب الحالي مخصص عمليًا للتطبيق وفق تأكيد المالك بأن الموقع لا يستعمل Cloudflare حاليًا؛ لا تشارك موارد التطبيق مع خدمات أخرى دون تخطيط للحصص.
- API العامة لا تحتوي على عمليات كتابة؛ ينبغي بناء لوحة إدارة محمية لاحقًا.

## الحالة التقنية

الشيفرة **نسخة تأسيسية (scaffold)** قابلة للمراجعة والتطوير، وليست إصدار متجر جاهزًا. يحتاج البناء الحقيقي واختبارات الأجهزة ونقل الملفات وإعداد نشر المتاجر.

## حصيلة الاستيراد الأول (8 ملفات)

تمت مطابقة MD5 لكل ملف PDF مع `ETag` للكائن المرفوع في R2، وحُفظت بصمات `SHA-256` بقاعدة D1 للتحقق عند تنزيل الملفات داخل التطبيق. يحتوي `scripts/imported-drive-audit.csv` على معرفات الملفات الأصلية لأغراض الإدارة فقط، ولا تعيد API العامة معرفات Drive أو عناوين R2 الداخلية.

- 3 ملفات للآداب الأصلية: القرآن والحديث والفكر الإسلامي.
- 2 ملفان للعلوم الطبيعية في الرياضيات والفيزياء/الكيمياء، إضافة إلى ملف فيزياء إضافي.
- ملفان لعلوم الحياة والأرض (النباتات البذرية والوراثة البشرية).
- العدد الإجمالي: 8، والحجم: 1,816,924 بايت. بقية مكتبة 50 GB لم تُنقل بعد.

## استيراد بقية المكتبة

**المحتوى نفسه لا يُضمّن داخل المستودع أو APK**؛ يبقى داخل R2. أداة `scripts/import_library.py` ترفع ملفات PDF المحلية وتتحقق من الأحجام وبصمة SHA-256، ثم تسجل بياناتها في D1. تحتاج إلى مفاتيح API محفوظة في متغيرات البيئة (انظر `scripts/.env.example`)، ولا تُحفظ هذه المفاتيح في التطبيق.

```bash
python -m pip install -r scripts/requirements-import.txt
python scripts/import_library.py scripts/library_manifest.example.csv --files-root . --dry-run
python scripts/import_library.py manifest.csv --files-root /path/to/pdfs --publish
```

الملف النموذجي يتطلب استبدال `pdfs/example-bac-math.pdf` بملف موجود. الاستيراد يقبل أسماء مفاتيح R2 ثابتة ولا ينشر الملف قبل نجاح التحقق. إذا وجدت تصنيفات جديدة، أضفها أولًا إلى D1. استيراد ملفات Google Drive بكميات كبيرة يحتاج تنزيلها أولًا ضمن حساب مخوّل، أو تجهيز أداة مستقلة تربط واجهتي Drive وR2 بإذن المالك؛ لم تُنقل بقية المواد تلقائيًا.

## مشروع مستقل على GitHub وبناء APK تجريبي

لا تعدّل المستودع الحالي الخاص بموقع النتائج أو تطبيقه. أنشئ مستودع GitHub جديدًا لهذا المشروع باستخدام `bash scripts/publish_github.sh` على جهاز مثبت عليه `gh` وسُجل الدخول إليه. يحوي المشروع GitHub Actions تبني APK للتجربة (Debug) وتعرضه كـArtifact. يتضمن مسار الإنشاء إضافة إذن الإنترنت إلى Android Manifest لإصدارات Android.

**الحدود الحالية:** لم تعمل أدوات Flutter SDK أو Android SDK في بيئة التحرير هذه، لذا لم تُنتج APK/IPA ولم يُجرَ اختبار متجر أو اختبار على هاتف. فحوص API المحلية ناجحة، ويمكن اختبار النشر الخارجي من جهاز لديه إنترنت بواسطة:

```bash
python scripts/verify_remote_api.py --check-download
```

عنوان `workers.dev` منشور في Cloudflare وقاعدة D1 وR2 مربوطة، لكن الوصول إلى عنوان الـHTTP العام لم يُتحقق منه من بيئة التطوير هذه. لا تدّعِ جاهزية المتاجر حتى تنجح الفحوص واختبارات الأجهزة والتوقيع ومراجعة الحقوق.
