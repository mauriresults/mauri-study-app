# Google Play upload key and small Android release

## What already works

- GitHub Actions `Build compact Android release previews` builds ARM32 and ARM64 release-mode APKs with R8/icon tree shaking and a 30 MB per-APK size cap.
- GitHub Releases workflow publishes preview APKs after checking main-branch provenance and SHA256 checksums.
- The app does not bundle any PDFs; downloads are optional after installation.
- GitHub Actions also builds an AAB **preview**, which is **not valid for Google Play submission** without your permanent, private upload signing key.

## One-time private Google Play signing setup

Use an isolated computer you trust. Create an upload keystore with `keytool` (Java JDK required):

```bash
keytool -genkeypair -v -keystore mauri-student-upload.jks -storetype PKCS12 -keyalg RSA -keysize 3072 -validity 10000 -alias mauri_upload
```

Choose unique, strong keystore and key passwords. Back up the keystore and passwords **offline**; do not commit, upload, paste, or send them to chat.

Create these four **repository Actions secrets** in GitHub Settings -> Secrets and variables -> Actions:
- `MAURI_UPLOAD_KEYSTORE_BASE64`: one-line base64 of the complete keystore file.
- `MAURI_UPLOAD_KEY_ALIAS`: `mauri_upload` or the alias selected at key creation.
- `MAURI_UPLOAD_KEY_PASSWORD`: private key password.
- `MAURI_UPLOAD_STORE_PASSWORD`: keystore password.

Generate base64 locally using `base64 -w 0 mauri-student-upload.jks` on Linux; on macOS use `base64 -i mauri-student-upload.jks | tr -d '\\n'`.

Then run GitHub Actions -> **Prepare Google Play signed AAB** -> Run workflow. This workflow generates platforms, configures signing **only on the ephemeral runner**, analyzes and tests Flutter, builds AAB in release mode, verifies the JAR signing and writes a SHA256 checksum. It publishes the signed AAB as a private-expiring GitHub Actions artifact, not as a public release.

The app package/application ID generated by `flutter create --org mr.mauri.study` should be reviewed and finalized **before first Play upload**, as changing it later is a new app. Store enrollment, privacy disclosures, store listings and required test tracks are not automated.

## Which download link to share with students?

Use the **compact ARM64 APK** from GitHub Releases for the large majority of current Android phones. Use ARM32 only for older 32-bit hardware. Never instruct users to install both simultaneously. Signing keys may differ from earlier debug previews; if an update fails due to incompatible signatures, back up any offline PDFs and app data before uninstalling the old test version.

The previous ~161 MB debug APK is for developer troubleshooting. The verified compact preview APKs are ~18.7 MB (ARM64) and ~16.2 MB (ARM32). In Google Play, upload a **production-signed AAB** and let Play select device-specific optimizations.

Official documentation: https://docs.flutter.dev/deployment/android
